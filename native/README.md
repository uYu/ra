# Ra AI 的 C++ / WebAssembly 核心

浏览器进阶 AI 使用 `ra_ai.cpp` 中的规则模拟、计分、局势估值、拍卖求解和信息集 MCTS。一次请求的所有模拟都在 Wasm 内执行，JS 只编码一次输入并读取一次结果。实际牌桌、界面、存档与回放继续由 TypeScript 引擎管理。

按用户要求，交互页面的“进阶 · 大祭司 · 2 秒思考”由 `src/game/ai.worker.ts` 显式传入 `timeMs: 2000`，显式使用 `horizon: "next-epoch"`（第一纪元到第二纪元结算，第二/三纪元到终局），生产核心为 `08f9cfe5…`；核心 API 与命令行未传时间预算时仍保留根候选数 ×32 默认。浏览器 Worker 返回搜索耗时和模拟数用于验证，强制行动可能立即返回；原 Wasm 故障回退保持。生产构建与 4 项实际 Worker 测试通过，包含原生搜索至少 1900ms 的检查。对手入树和奖励/树深消融仍为隔离原型，定制出价裁剪已撤回；历史实验全部完成或停止，快照保留。

策略和默认预算保持与 TypeScript 参考一致：总预算为根候选数 × 32 次，UCT 自适应分配访问；共享根场景、递减策略引导、对手倾向采样和公开信息隔离均保留。此次迁移不据速度推断胜率提高。浮点估值按容差检查，不承诺跨运行时逐比特一致。

## 构建

仓库保留 `src/game/ai/ra-ai.wasm`，因此普通前端构建与 Docker 构建只需要 Node.js，不需要安装 C++ 工具链。

更改 C++ 后，需要 PATH 中有 Emscripten 的 `em++`，然后执行：

```bash
npm run build:wasm
npm run verify:wasm
npm test
npm run build
```

构建脚本使用临时目录中的 Emscripten 缓存，必要时复制现有只读缓存。也可通过 `EM_CACHE` 指定可写缓存，通过 `EMXX` 指定编译器。默认缓存路径先解析符号链接，避免 macOS `/var` 与 `/private/var` 的相对路径问题。

`wasm-build.json` 保存 ABI 版本、编译器、编译选项和源码/产物 SHA-256。普通构建、测试和命令行模拟会先验证，防止源码改动后误用旧二进制。更新规则时必须同步两套引擎、重新生成 Wasm 并运行一致性检查。

## 运行与回退

`src/game/ai.worker.ts` 在进阶难度加载 `wasm.ts`。Vite 将二进制打包为带哈希文件名的独立资源，加载路径相对于 Worker，支持相对部署路径。无需共享内存或跨源隔离配置。

加载失败、编译失败、返回非法行动或下载超过 5 秒时，Worker 回退到 TypeScript 搜索，并返回 `backend` 和 `fallback` 诊断字段。入门与标准难度直接使用 TypeScript，不加载 Wasm。暂停/弹窗取消仍通过终止当前 Worker 完成。

同步函数 `chooseAction()` 继续作为 TypeScript 参考与回退入口；浏览器进阶 Worker 和 `npm run simulate -- N hard` 使用 C++。性能对照命令：

```bash
npm run benchmark:wasm -- artifacts/ai-wasm-benchmark.json
```

这个对照包含 JS 状态编码、公开信息处理和结果解码，双方使用相同局面与模拟预算；模块首次实例化单独计时。它不包含 HTTP 下载、Worker 创建或界面动画/固定思考展示停顿。

## 数值协议

边界使用版本化的 Float64 数值缓冲区；状态中的整数通过数值传输。C++ 校验长度、索引范围、协议版本和预算，JS 在返回前再次确认行动合法性。内存增长后重新获取结果视图。

- 导出：`abi_version`、`input_ptr`、`output_ptr`、`run`，以及编译器的内存/初始化导出。
- ABI 6 的 `run(op, length, samples, horizon, variant, timeMs)`：0 搜索，1 单步规则模拟，2 估值/纪元得分，3 策略，4 合法行动，5 搜索候选，6 完整拍卖续着，7 价值模型特征/推理诊断，8 续局策略模型特征/评分诊断。搜索输入在状态后依次追加价值模型与续局模型块，最后追加奖励枚举（0 为默认 relative，1 为实验 future-rank）：0 表示不用该模型；1 后接输入维度、隐藏层大小和权重。价值模型为91维、最多48隐藏单元，续局模型为287维、最多16隐藏单元；缓冲区16384个Float64，支持两类模型的最大组合。续局模型权重须为有限数且绝对值不超过1e6。实验模型按调用传入，不保存为全局状态。`horizon` 为 0（本纪元）、1（终局）、2（本纪元及下一纪元）；`variant` 为 0（UCT）、1（根 SH）、2（DPW）；`timeMs=0` 使用固定模拟预算，非零使用软计算时限。状态缓冲区格式仍为版本 1。
- 只有搜索入口用于生产决策，调用前重新构造公开剩余牌集合、清除种子与隐藏分数。其余操作用于与 TS 参考逐状态比对，可以保留测试传入的袋序和分数。
- 原生模拟不生成中文日志或历史展示数据；一致性检查比较规则状态、牌序、拍卖过程与分数，展示数据由 TS 引擎产生。
- 等时搜索通过 WASI `clock_time_get` 读取桥接的单调时钟。模块初始化后赋值导出的内存引用，每次写时钟数据重新建立视图，以兼容内存增长。没有时间预算的调用保持确定性。

## 论文算法对照

TS 与 C++ 均支持 `variant: "uct" | "sh" | "dpw"`，默认仍为 UCT。`timeMs: 200` 表示在完整模拟之间检查 200 ms 软时限；最低根候选覆盖和最后一次模拟可能超时，不能假设返回耗时严格等于 200 ms。固定次数 SH 与等时 Anytime SH 使用不同的、分别有文献依据的调度。

当前核心支持显式 `timeMs: 1–2000`；冻结的历史核心仍保留各自上限。默认仍为固定模拟预算。2 秒预算对默认预算的诊断对照命令如下，只有被测座位使用 2 秒，其余座位保持根候选数 × 32；双方使用同一当前核心、UCT、本纪元、原奖励，不传学习模型。完整棋谱在写入前经正式引擎逐局回放验证。汇总会再次验证完整性、棋谱、预算与种子/座位覆盖，并按整个种子区组计算区间，拒绝把中断对局当作完整结果。

```sh
npm run benchmark:tree -- --engine current --variants uct --modes time --opponent-fixed yes --time-ms 2000 --samples 32 --seeds 6 --start 910001 --counts 2,3,4,5 --jobs 6 --costs off --out artifacts/ai-uct2s-control.json
npm run report:budget -- artifacts/ai-uct2s-control.json
npm run monitor:budget -- artifacts/ai-uct2s-control.json 8787
```

## 跨纪元搜索验证

2026-10-28 按用户要求，可玩进阶 Worker 显式使用 `horizon: "next-epoch"` 和 2000ms；`chooseAction(..., "hard")` 的 TS 回退采用相同时域。底层 `search`/`searchAction` API 的历史默认仍为 `epoch`，用于保留旧实验和固定工作量复现。此次不改 C++/Wasm 二进制，不合入隔离的对手入树原型，也不重启已停止的实验。以下为原跨纪元模式及历史验证设计。

`search(state, { horizon: "next-epoch" })` 在每次模拟中继续执行纪元切换，直到下一纪元计分结束；从第二或第三纪元开始则模拟至终局。它使用原有估值、对手模型、UCT 和根候选数 × 32 次总预算，不增加针对特定牌的策略。转移上限为 480 步，搜索报告的 `truncated` 记录没有抵达目标的模拟数；默认 `epoch` 上限 240 步，完整 `game` 上限 720 步。每个拍卖续着内部也检查终止条件和步数上限。

独立验证使用固定的 12001–12006 种子，2–5 人分别轮换全部座位，每组 84 局；11001 起的种子留给单独的试验，不与验证集合混用。此次不根据验证结果调参。

本次验证结果公开后，12001–12006 就不再是新版本的未见数据。后续调参应使用试验集合，并用 `--start 13001` 等新范围另做最终验证，输出到新的结果文件；不要覆盖历史报告后宣称使用了新的独立验证。

```bash
# 同模拟预算：下一纪元 32 对本纪元 32
npm run benchmark:horizon -- --split validation --seeds 6 --counts 2,3,4,5 --jobs 3 --out artifacts/ai-next-epoch-validation.json
# 更多计算预算的对手：下一纪元 32 对本纪元 64
npm run benchmark:horizon -- --split validation --seeds 6 --counts 2,3,4,5 --opponent-samples 64 --jobs 3 --costs off --out artifacts/ai-next-epoch-budget-control.json
```

脚本使用多个计算线程并保存完整局面的逐局统计与进度检查点。并发对战耗时只作诊断；延迟比较取第一组启动前单独执行的 24 局面预热测试。两组均为固定模拟预算，64 次对手是耗时接近的额外对照，不能称为逐手严格等时。胜负按正式规则用最高圆盘打破同分；轮换座位的比赛共享种子，不能按每局独立计算统计置信度。

## 当前研究状态

### 2026-10-28 隔离性能剖析

在 2 秒预算对照继续运行期间，另外用一个进程对 24 个固定公开局面做 CPU 采样：2–5 人 × 三纪元 × 普通回合/竞价各一局面，取确定性标准策略对局的各阶段中间样本。固定根候选 ×128 重复三次，另做每局面 2000ms 采样一次；共保存 16 份原始 `.cpuprofile`。剖析副本以相同 O3 参数额外保留函数名，去除自定义节后，其全部执行/数据节与当时生产 Wasm 逐字节一致，24 个局面的固定预算搜索报告也完全一致。原对照代码、Wasm、参数和进程未改动，前后核对计划中的源文件哈希均通过。

2 秒采样的主要互斥归因如下。内存列包括可识别的分配/释放和内存函数，状态复制列只含其自身工作；复制中调用分配器的部分归入内存列。采样和优化内联会限制精确归属，不能将这些数字当作逐函数精确计时。

| 人数 | 估值计算 | 内存管理 | 状态复制自身 | 公开局面键 |
|---|---:|---:|---:|---:|
| 2 | 30.7% | 27.6% | 7.3% | 13.3% |
| 3 | 34.5% | 34.2% | 9.7% | 3.2% |
| 4 | 38.4% | 31.4% | 9.5% | 3.4% |
| 5 | 42.4% | 30.6% | 8.4% | 1.5% |

包含子调用的 `auctionPlan` 在 2/3/4/5 人局分别占 55.0%/71.0%/72.4%/79.7%；这些调用链数字与上表重叠，不能相加。五人局中递归/拍卖控制的互斥归因约 9.1%，`exp` 自身约 17.1%。全部 2 秒采样的 99.6% 样本落在 Wasm 函数自身；可识别内存函数样本中，约 52% 的调用栈可追溯至状态复制或析构。

剖析提出减少假设拍卖结果时的完整 `State`/`Player` 深复制及动态分配，复用同一获胜者不同圆盘之间不变的藏品统计、法老比较和概率项，再评估拍卖后缀 `(index, high, winner)` 记忆化与只预计算可达结果。两人局还应单独检查公开局面键的复制、排序和逐字节追加。这是剖析时的建议；对战结束后已完成下述等价优化。尚无新棋力对战结论。

剖析与原六线程对战并行，降低调度优先级的请求被本机沙盒拒绝，因此不宣称低优先级或独占机器测得的绝对延迟；采样器也会影响计时模式下实际完成的模拟量。完整结果见 `artifacts/ai-perf-20261028/findings.json`，两种预算原始汇总分别位于该目录与 `artifacts/ai-perf-20261028-2s/summary.json`。复现时为输出使用新目录，保留当前生产文件：

### 等价性能优化与完整复查

当前实现保留原搜索、收益、候选行动及浮点运算顺序，ABI 仍为 6。主要变化为：

- 拍卖假设结果共用工作状态，按当前最高出价和剩余竞价者预计算可达结果；同一获胜者不同圆盘复用藏品、法老比较和机会概率。
- 圆盘排名使用小计数数组，竞价排序和候选使用栈数组；容量覆盖协议允许的 16 可用盘与 16 已用盘在纪元切换后合并的 32 个盘。
- 法老数量差 −25…25、两种既有宽度的概率因子按原公式初始化查表，范围外回退原公式；无近似指数函数。文明/古迹种类用位掩码及 `popcount`，古迹种类分用小表，重复古迹分与二连数量在统计时维护。
- 牌目录缓存紧凑类型码；公开局面键用 96 项计数表及两个 64 位存在掩码，位扫描按原顺序输出，直接写入原来的小端整数编码。计数为 16 位，覆盖规则状态与诊断输入中的较大重复集合。

最终构建在原来的 24 个公开局面上串行比较原版、首轮优化和最终版：固定根候选 ×128 重复三轮，完整报告逐项一致；2 秒预算每局面每版本一轮，按局面轮换三个版本的执行顺序。全量测试和 CPU 剖析均未与最终计时测量并行。原始逐次记录见 `artifacts/ai-perf-lut-final-20261028.json`。

| 人数 | 原版每 2 秒模拟数 | 首轮优化 | 最终版 | 最终/原版 |
|---|---:|---:|---:|---:|
| 2 | 18,064 | 22,777 | 29,842 | 1.65× |
| 3 | 7,551 | 12,590 | 14,508 | 1.92× |
| 4 | 7,750 | 11,688 | 14,271 | 1.84× |

隔离诊断得到两个可复现线索。第一，报告的候选 `value` 是原始相对分差均值，UCT实际优化每次收益先 `tanh(v/20)` 后的均值，再按访问次数推荐。一次2秒复现中，1/4的原始均值为7.0050/6.9845，变换后均值为0.306466/0.307439，顺序发生逆转；这是额外风险偏好，不能直接等同于“平均分差最大”。第二，同一组4096个场景、固定原续局策略时，1/4均值为8.9615/7.9730，配对差0.9884；完整树搜索把二者估计到近乎相同并选4，根层或两层树的诊断则选1。线性回传的隔离2秒诊断也选1，原奖励下UCT/SH/DPW均选4。

这些是目标与搜索结构敏感性的证据，**尚未定位唯一实现缺陷，也未验证通用修复**。线性回传同时改变收益尺度与探索力度，树深变化也改变续局策略，不能仅凭这一题把任何设置作为新默认。生产未改奖励、UCT参数或树深，没有新对战。
